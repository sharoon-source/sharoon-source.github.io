01PROJECT 01 / 03

Ball & Beam Balance System

A ball resting on a horizontal beam is inherently unstable — left alone, gravity rolls it off the edge. This system keeps it centered in real time: a time-of-flight sensor tracks the ball's position, and a PID loop on an Arduino continuously re-angles the beam to correct it. The beam dynamics were modeled from Newton's second law before any control code was written, then built from laser-cut acrylic, 3D-printed brackets, and a PVC beam driven through a GT2 pulley system.

Closed-loop PID control·0.01mm laser-cut tolerance·modeled from Newton's 2nd law
01Closed-loop PID control

An Arduino Uno runs a PID loop that reads the ball's position every cycle and adjusts beam angle to recenter it, starting from gains of Kp 0.5, Ki 0.0, Kd 0.1 and tuned iteratively from there.

02Time-of-flight position sensing

A VL53L0X distance sensor measures how far the ball is from center along the beam channel, feeding that position error straight into the control loop.

03Physics-first modeling

Before writing any control code, we derived the ball's motion (m·ẍ = −mg·sin θ) and the beam's rotation about its pivot (I·θ̈ = mg·x·cos θ) from Newton's second law, so the PID design was grounded in the actual dynamics rather than trial and error.

04Supervisory state machine

The system moves through an idle state, a three-stage balancing sequence — ball detection, angle adjustment, stabilizing — and an emergency-stop/error state that catches sensor failures or a manual stop and routes back to a resolving step.

05Mixed-manufacturing build

Laser-cut acrylic (0.01mm tolerance) formed the flat structural plates, 3D-printed parts handled the more complex geometry, and a hand-cut PVC pipe became the beam's ball channel — driven by a 12V JGY-370 motor and gearbox through a GT2 belt and pulley on a press-fit bearing.

02PROJECT 02 / 03

Intelligent Serving Robot

Most tennis-serve machines are built for competitors — $900 to $6,000, with no awareness of where the player is standing. This one is built for casual players: a Raspberry Pi camera tracks the player and aims the machine, a stepper-fed hopper loads one ball at a time, and two motors launch it through a flexible tube. Two full design generations and a few motor and wiring failures later, the finished prototype held its own against the spec.

18m launch range·$445 build cost·target under $400
01Autonomous player tracking

A Raspberry Pi and camera module run real-time player detection, driving a 20kg heavy-duty servo to keep the machine aimed at the player horizontally as they move around the court. Vertical launch angle is set manually.

02Single-ball feed system

A stepper motor rotates a filter disc in 90° increments, releasing exactly one ball at a time from the hopper into a flexible feed tube — controlling the pace of play and keeping the machine from jamming or double-feeding.

03Back-loading launch mechanism

Two RS540 high-torque DC motors spin foam wheels mounted behind the exit tube; the ball is fed in directly behind them and shot out at speed, powered through a 12V/5A supply and a dedicated motor driver on an Arduino Mega.

04Sized from real calculations

Impact-force analysis (F·Δt = m·Δv ≈ 6.84N) and projectile-motion calculations — targeting an exit velocity around 130mph to hit real serve speeds — set the motor and structural requirements before parts were ever ordered.

05Two design generations

A Fall 2023 tripod concept gave way to a wheeled, boxed Winter 2024 rebuild chosen for portability and a lower center of gravity. Getting there meant swapping underpowered motors for the RS540s, upgrading the wiring after one round melted under load, and flipping the feed geometry from front- to back-loading.

03PROJECT 03 / 03

Obstacle-Avoiding Robot Car

A ground-up obstacle-avoiding robot: three ultrasonic sensors watch the front, left, and right sides, and an Arduino decides in real time whether to keep driving, back up, or pivot around whatever it just found. Four DC motors on a self-built acrylic chassis, driven through an Adafruit Motor Shield, give it 4-wheel-drive and the ability to spin in place instead of steering like a car.

3 ultrasonic sensors·20cm avoidance threshold·4WD drivetrain
01Reactive obstacle avoidance

Every loop the Arduino reads all three sensors; if anything comes within 20cm it stops, reverses briefly, then pivots toward whichever side has more open space before moving forward again.

02Three-point ultrasonic sensing

HC-SR04 sensors mounted front, left, and right give the car a wide field of awareness without needing a scanning or panning sensor.

034WD drivetrain

Four DC motors wired through an Adafruit Motor Shield (AFMotor library) run in matched pairs for forward and reverse, and release independently per side to pivot in place.

04Self-built chassis

A laser-cut acrylic deck stack holds the electronics, sensors, and motor mounts, wired point-to-point rather than built on a pre-made robot kit board.

05Tunable control loop

Obstacle distance, reverse time, and pivot duration are just a handful of constants in the code — easy to retune once you see how the car actually behaves on the floor.

obstacle_avoidance.ino 

#include <AFMotor.h>

AF_DCMotor motor1(1);
AF_DCMotor motor2(2);
AF_DCMotor motor3(3);
AF_DCMotor motor4(4);

const int trigPinFront = A4;  // Front ultrasonic sensor
const int echoPinFront = A3;
const int trigPinLeft = A1;   // Left side ultrasonic sensor
const int echoPinLeft = A0;
const int trigPinRight = A5;  // Right side ultrasonic sensor
const int echoPinRight = A2;

long duration;
int distanceFront;
int distanceLeft;
int distanceRight;

void setup() {
  // Set the speed for all motors
  motor1.setSpeed(100); // Rear Left
  motor2.setSpeed(100); // Rear Right
  motor3.setSpeed(100); // Front Right
  motor4.setSpeed(100); // Front Left

  pinMode(trigPinFront, OUTPUT);
  pinMode(echoPinFront, INPUT);
  pinMode(trigPinLeft, OUTPUT);
  pinMode(echoPinLeft, INPUT);
  pinMode(trigPinRight, OUTPUT);
  pinMode(echoPinRight, INPUT);
}

void loop() {
  // Get the current distances using the ultrasonic sensors
  distanceFront = getDistance(trigPinFront, echoPinFront);
  distanceLeft = getDistance(trigPinLeft, echoPinLeft);
  distanceRight = getDistance(trigPinRight, echoPinRight);

  // If sensor detects an obstacle < 20 cm
  if (distanceFront <= 20 || distanceLeft <= 20 || distanceRight <= 20) {
    reverse();
    delay(200);

    // Move to the direction with no obstacles
    if (distanceLeft > distanceRight) {
      // Move left
      pivotLeft();
    } else {
      // Move right
      pivotRight();
    }

    // Move forward
    moveForward();
  } else {
    moveForward();
  }

  delay(100);
}

void moveForward() {
  motor1.run(FORWARD); // Rear Left
  motor2.run(FORWARD); // Rear Right
  motor3.run(FORWARD); // Front Right
  motor4.run(FORWARD); // Front Left
  delay(500);
}

void pivotLeft() {
  motor1.run(FORWARD); // Rear Left
  motor2.run(RELEASE); // Rear Right
  motor3.run(RELEASE); // Front Right
  motor4.run(FORWARD); // Front Left
  delay(1000);

  stopMotors();
}

void pivotRight() {
  motor1.run(RELEASE); // Rear Left
  motor2.run(FORWARD); // Rear Right
  motor3.run(FORWARD); // Front Right
  motor4.run(RELEASE); // Front Left
  delay(1000);

  stopMotors();
}

void reverse() {
  motor1.run(BACKWARD); // Rear Left
  motor2.run(BACKWARD); // Rear Right
  motor3.run(BACKWARD); // Front Right
  motor4.run(BACKWARD); // Front Left
  delay(10);
}

void stopMotors() {
  motor1.run(RELEASE);
  motor2.run(RELEASE);
  motor3.run(RELEASE);
  motor4.run(RELEASE);
  delay(100);
}

int getDistance(int trigPin, int echoPin) {
  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);
  duration = pulseIn(echoPin, HIGH);
  return duration * 0.0344 / 2;
}
